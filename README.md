## 🛠️ Архитектура проекта и Спецификация WebSockets API

В рамках данного домашнего задания реализован интерфейс корпоративного чата, работающий в реальном времени. Взаимодействие между клиентом и сервером построено на базе **WebSockets (протокол `ws://`)** с использованием гибридного сервера на базе **Express** (порт `3000`).

### 📡 Протокол обмена данными (Двунаправленный Full-Duplex)

Все сообщения передаются по сетевому сокету в формате сериализованных строк JSON. Сервер и клиент обрабатывают события на основе свойства `type` или структуры пришедшего пакета.

#### **1. Авторизация и создание пользователя (HTTP REST)**
Перед подключением к сокету фронтенд проверяет уникальность имени через стандартный HTTP-запрос.
*   **[POST]** `http://localhost:3000/new-user`
    *   *Тело запроса:* `{ "name": "имя_пользователя" }`
    *   *Ответ (Успех 200):* `{ "status": "ok", "user": { "id": "uuid", "name": "имя" } }`
    *   *Ответ (Ошибка 409):* `{ "status": "error", "message": "This name is already taken!" }`

#### **2. Регистрация сессии в сокете (Client → Server)**
После успешного HTTP-ответа клиент открывает WebSocket и привязывает имя к соединению:
```json
{
  "type": "login",
  "name": "имя_пользователя"
}
```

#### **3. Синхронизация списка участников (Server → Client)**
При входе нового пользователя или при отключении старого, сервер делает *broadcast* (вещание) текущего массива всех активных участников. Данные приходят в виде **чистого JSON-массива в корне пакета**:
```json
[
  { "id": "uuid-1", "name": "Alexandra" },
  { "id": "uuid-2", "name": "Dusty" }
]
```
*Фронтенд автоматически заменяет имя текущей сессии на индикатор `You` и выравнивает его в левой панели.*

#### **4. Отправка и ретрансляция сообщений (Bidirectional)**
*   **От клиента на сервер (Client → Server):**
    ```json
    {
      "type": "send",
      "message": "Hello world!",
      "user": { "id": "my-uuid", "name": "You" },
      "timestamp": 1711234567890
    }
    ```
*   **От сервера всем участникам (Server → Client / Broadcast):** Сервер дублирует этот пакет всем подключенным устройствам. Фронтенд сравнивает `user.id` сообщения с ID текущего пользователя: если они совпадают, блок смещается вправо (**Right / Outgoing**), иначе — влево (**Left / Incoming**).

#### **5. Безопасное отключение и защита от "призраков" (Client → Server / Hardware Drop)**
Для предотвращения зависания мертвых сессий в памяти сервера реализована двухконтурная система очистки:
*   При штатном закрытии вкладки или нажатии кнопки выхода клиент шлет: `{ "type": "exit", "user": { "name": "имя" } }`.
*   При аварийном падении сети или выключении устройства сервер перехватывает событие по аппаратному триггеру `ws.on('close')`, извлекая имя из сохраненной сессии `ws.currentUserName`.
